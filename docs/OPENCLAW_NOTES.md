## 3. Архитектура в двух абзацах

Шлюз (gateway) это один Node-процесс. В нём живут каналы (Telegram и т. д.), агентный цикл, плагины, cron и веб-панель. Конфиг: JSON5 в `~/.openclaw/openclaw.json`. Модель: `agents.defaults.model` плюс провайдеры в `models.providers`.

Важное следствие: **нативные плагины работают внутри процесса шлюза и делят его границу доверия** (`docs/plugins/architecture.md`, «Execution model»; `supported-capability-matrix.md`). Песочница изолирует только *выполнение инструментов* (shell, файловые операции), но не шлюз, не плагины и не MCP. Поэтому ferrum-policy и ferrum-modes входят в доверенную базу: ошибка в них ломает всю защиту, а плагин сторонних авторов получает права шлюза. Отсюда правило из задачи «чужие плагины не ставим без полного чтения кода».

## 4. Песочница: что именно доказано

**[запущено]** на базовом конфиге (`sandbox.mode: "all"`, `exec.host: "sandbox"`, `elevated.enabled: false`):

- Список инструментов, разрешённых в песочнице, ровно такой: `exec, process, read, ls, write, edit, apply_patch, view_image, sessions_list, sessions_history, sessions_search, sessions_send, sessions_spawn, sessions_yield, subagents, session_status`.
- По умолчанию запрещены: `browser, canvas, computer, mobile_ui, nodes, automations, gateway` и все инструменты каналов.
- Чужие плагинные инструменты в песочнице разрешаются только через `tools.sandbox.tools.alsoAllow`.
- `tools.elevated.enabled=false` закрывает путь «выйти из песочницы на хост».
- Бэкенд `podman` проходит валидацию и даёт тот же набор инструментов (тест «podman»).

### Инвентарь возможных выходов на хост (что закрывать конфигом и тестами на этапе 1)

| Путь на хост | Почему опасен | Мера |
| --- | --- | --- |
| Песочница **выключена по умолчанию**, `exec` идёт на хост без одобрений (`mode=full`) | дефолт небезопасен | явный конфиг, контрактный тест, что `sandbox explain` показывает песочницу |
| `sessions_spawn runtime:"acp"` | ACP-рантайм запускается **на хосте**, а `sessions_spawn` в песочнице разрешён | `acp.enabled: false`, тест на этапе 1 |
| Cron «command payload» и инструмент `automations` | исполняются на хосте шлюза | `automations` в deny (уже по умолчанию), cron-задачи только агентного типа |
| Команды чата `/bash`, `/exec`, `/elevated`, `/config` и др. | дают хост-доступ или правку конфига | `commands.bash/config/mcp/plugins/debug/restart: false` (первые по умолчанию выключены, но фиксируем явно) |
| 41 плагин включён по умолчанию (browser, canvas, file-transfer, linux-node, cua-computer, device-pair, …) | лишняя поверхность | `plugins.allow` с минимальным списком |
| `view_image`, `pdf` читают файлы | возможное чтение хостовых путей | тест на этапе 1: путь вне workspace должен давать отказ |
| `docker.binds`, проброс `docker.sock` | прямой доступ к хосту | не использовать, тест на конфиг |
| MCP stdio-серверы | запускаются на хосте | только свои/вычитанные, этап 5 |

## 5. Плагинный API → функции Ferrum

Всё **[документация]**, пока не упражнялось. План проверки на этапе 2.

| Функция Ferrum | Механизм OpenClaw |
| --- | --- |
| Жёсткие запреты и подтверждения в local-режиме | `api.on("before_tool_call", ...)`: результат `{block, blockReason, params, requireApproval}`. Таймаут хука 15 с, при сбое **закрыто** (fail closed) |
| Диалог подтверждения | `requireApproval`: заголовок, описание, `severity`, `allowedDecisions`, `timeoutMs` (макс. 600000, без ответа = отказ). В Telegram через inline-кнопки или `/approve <id> allow-once\|deny` |
| Только свои инструменты для хоста | `api.registerTool(factory)`; фабрика получает `sessionKey, agentId, sandboxed, senderIsOwner, workspaceDir`, возврат `null` **прячет** инструмент. Так `local_*` невидимы в режиме sandbox |
| Режим сессии | `api.registerCommand` (имя `mode` не зарезервировано) и `api.session.state.registerSessionExtension` для состояния на сессию |
| Режим в системном промпте | `before_prompt_build` → `appendSystemContext`. Для не встроенных плагинов нужно `plugins.entries.<id>.hooks.allowConversationAccess: true`. Может только **сужать** `toolsAllow` |
| Аудит | `before_tool_call` и `after_tool_call` |
| Доверенная политика | `api.registerTrustedToolPolicy`, требует `contracts.trustedToolPolicies` в манифесте |

Манифест плагина: `openclaw.plugin.json` плюс `package.json → openclaw.extensions`. Подключение: `plugins.load.paths` или `openclaw plugins install --link`. Есть `openclaw plugins init/build/validate`.

Cron-сессии имеют ключ `cron:<jobId>`, поэтому «режим на сессию, по умолчанию sandbox» автоматически даёт «cron идёт в sandbox». Включение local в конфиге задачи надо реализовать отдельно.

## 6. Подтверждения и UX кнопки «Подтвердить» для `/mode local`

Проблема, найденная в API: обработчик команды (`registerCommand`) **не имеет доступа к API подтверждений**. Варианты:

- **A.** Команда `/mode local` ставит состояние «ожидает» и отвечает с `continueAgent`. Агент обязан вызвать инструмент `ferrum_enable_local`, а вызов этого инструмента защищён `requireApproval`. Плюс: целиком в публичном API. Минус: подтверждение проходит через цикл агента и модель, которую можно сбить.
- **B.** Плагин сам вызывает RPC шлюза `plugin.approval.request` (клиент `GatewayClient` экспортируется из `plugin-sdk/gateway-runtime`). Плюс: не зависит от модели. Минус: менее документированный путь.

Решение принимается спайком на этапе 2. Склоняюсь к B, если он заработает: подтверждение режима не должно зависеть от модели.

Для кнопок нужны `channels.telegram.capabilities.inlineButtons` и определённые подтверждающие (`commands.ownerAllowFrom`, `execApprovals.approvers`).

## 7. Каналы, allowlist, pairing

- Telegram: `dmPolicy: "allowlist"` и числовой `allowFrom` с твоим user id. Pairing (код привязки) не используем.
- **Частично нативно**: чужие отправители игнорируются, но запись в журнал есть только на уровне `logVerbose`. Требование «игнорировать и логировать» полностью закроет ferrum-аудит (журнал отказов).
- Всё, что пришло из сообщений и интернета, считается недоверенным. Это правило промпта и политики, самого механизма «taint» в OpenClaw нет.

## 8. Аудит: пробел

Встроенный журнал (`docs/gateway/audit.md`) хранит только метаданные и **никогда не пишет аргументы и результаты инструментов**. Ferrum должен вести свой журнал через `before_tool_call`/`after_tool_call`: время, сессия, **режим**, инструмент, аргументы (с вычищенными секретами), решение политики, результат (усечённый). Файл в `~/.ferrum/audit/`, вне workspace, вне досягаемости песочницы.

## 9. Лимиты: пробел

Нативно есть только `agents.defaults.timeoutSeconds` (по умолчанию 48 часов, ставим явно, например 600) и `tools.loopDetection` (по умолчанию выключено). Лимитов «максимум шагов» и «максимум токенов на задачу» нет. Ferrum реализует их в плагине (счётчик вызовов инструментов на ход и бюджет токенов).

## 10. Навыки, память, cron, браузер, MCP, Google, Discord, WhatsApp

- **Навыки:** `security.installPolicy` умеет запускать внешнюю команду для проверки устанавливаемых навыков и плагинов. Кандидат для политики «ничего не ставить автоматически» (этап 4).
- **Память:** `memory-core` по умолчанию создаёт управляемую cron-задачу «dreaming». Это тратит токены, нужно решить на этапе 4 (выключить или оставить).
- **Cron:** см. раздел 4 про command payload. Автозапуск на Windows требует одноразовой задачи планировщика (этап 6).
- **Браузер:** в песочнице только через Docker-движок (отдельный контейнер Chromium плюс noVNC). С Podman песочничного браузера **нет**. Для local-режима есть документ про удалённый CDP из WSL2 в Windows (`docs/tools/browser-wsl2-windows-remote-cdp-troubleshooting.md`).
- **Google:** навык `gog` хранит OAuth на хосте, что противоречит «секреты не попадают в песочницу», если вызывать его из песочницы. План этапа 5: MCP-сервер или плагин на хосте шлюза, токены в защищённом хранилище, вызов только через ferrum-policy с подтверждением отправки.
- **Discord:** штатный канал (`docs/channels/discord.md`).
- **WhatsApp:** штатный канал на неофициальной библиотеке Baileys. Предупреждение про риск блокировки номера и рекомендация отдельного номера будут на этапе 7.

## 11. Топология Windows: оценка рисков

Схема «шлюз в WSL2, local-режим через `powershell.exe` по interop» осуществима, но с оговорками, которые надо проверить **на твоей машине**:

1. **Повышенные права через interop.** Если WSL запущен из терминала «от администратора», `powershell.exe` в interop может оказаться с повышенными правами. Preflight это проверяет, а ferrum-policy обязан перепроверять при каждом запуске и отказывать.
2. **Пути.** Рабочая папка песочницы в WSL (`~/ferrum/workspace`, ext4), а не `/mnt/c`: так быстрее и без прав Windows. Local-режим работает в `%USERPROFILE%\ferrum-workspace`.
3. **Автозапуск** до входа в систему требует задачи планировщика «WSL Boot» (запуск `wsl.exe -d <distro> --exec dbus-launch true`) и `loginctl enable-linger`. Это известная проблема WSL (#13416). Этап 6, нужна одноразовая админ-команда.
4. **Альтернатива** (не выбрана): компаньон Windows Hub в режиме node с `system.run`, или шлюз нативно в Windows. Если interop окажется непригодным, остановлюсь и предложу это, не переделывая молча.

| Функция | OpenClaw даёт | Ferrum пишет |

## 13. Неожиданности (для быстрого просмотра)

1. Песочница выключена по умолчанию, `exec` на хосте без одобрений.
2. ACP-рантайм обходит песочницу, а `sessions_spawn` в ней разрешён.
3. 41 плагин включён из коробки.
4. `memory-core` сам заводит cron-задачу «dreaming».
5. Встроенный аудит не хранит аргументы.
6. Нет лимитов на шаги и токены.
7. Права конфига: при мире-читаемом `openclaw.json` `security audit` выдаёт critical (лечится `chmod 600`).
8. `GET /` открыт без токена.
9. Источник правды по версиям: пакет из npm содержит документацию, но **не** содержит скриптов установки образов песочницы. Образ придётся собирать вручную.
10. Модель по умолчанию `openai/gpt-6-astra`, ничего не настроено.

## 14. Решение по контейнерному бэкенду (нужен твой выбор)

Исходный план предполагал Docker Desktop. Ты сказал, что его не поставишь (свободно 4 ГБ). Песочница без контейнерного рантайма невозможна, поэтому вот варианты, все **без Docker Desktop**:

| Вариант | Что это | Песочничный браузер | Размер (оценка) |
| --- | --- | --- | --- |
| **A. Docker Engine внутри WSL** | `apt install docker.io` в Ubuntu | **Да** (но образ браузера большой, этап 3 на 4 ГБ не влезет) | движок ~0.3 ГБ + образ ~0.4 ГБ |
| **B. Podman в WSL** (rootless) | штатный `sandbox.backend: "podman"`, без демона | **Нет** | движок ~0.15–0.25 ГБ + образ ~0.4 ГБ |
| **C. SSH-бэкенд** | команды идут на другой машине (отдельный дистрибутив WSL или VPS) | Нет | отдельный дистрибутив места не экономит; VPS не занимает место, но платный |

Образ песочницы по умолчанию: Debian bookworm-slim + bash, ca-certificates, curl, git, jq, python3, ripgrep. Node в нём нет. Образ нужно собирать вручную, потому что в npm-пакете нет setup-скриптов (`docs/gateway/sandboxing/images-and-setup.md`). Для Podman rootless нужен ненулевой `docker.user` (`podman-backend.md`).

Preflight теперь печатает свободное место и предупреждает.

## 17. Находки этапа 1 (проверены запуском)

Подробности и порядок установки: `docs/STAGE1.md`.

1. **Fail-closed, слой 1.** Если `docker` недоступен, ход агента падает с `SandboxProvisioningError` ещё до обращения к модели. Откат на хост не происходит. Тест: `tests/isolation/run.mjs`.
2. **Fail-closed, слой 2.** При выключенной песочнице и `tools.exec.host: "sandbox"` инструмент `exec` отказывает («requires a sandbox runtime for this session»). Поэтому в Ferrum `exec.host` всегда `sandbox`, а не `auto`.
3. **Горячая перезагрузка применяет `agents.defaults.sandbox.mode` на лету** (лог `[reload] config hot reload applied (agents.defaults.sandbox.mode)`). Тот, кто может записать файл конфига, выключает песочницу без перезапуска. Меры: `chmod 600`, `commands.config: false`, `channels.telegram.configWrites: false`, инвариант в `scripts/check-config.mjs`; на этапе 2 ferrum-policy должен ещё и запретить правку конфига из workspace/local-режима.
4. **Host-exec наследует окружение шлюза.** В контрольном прогоне (sandbox off, `exec.host=gateway`) переменные с «секретами» шлюза были видны команде (4 совпадения). Песочница окружение шлюза не наследует (документация: `Sandbox exec does not inherit host process.env`; реальная проверка в тесте у тебя). Для **local-режима этапа 2** это требование: `local_exec` обязан запускать PowerShell с вычищенным окружением (allowlist переменных), иначе секреты шлюза утекут в команды.
5. **`/tools/invoke` жёстко запрещает `exec`** (RCE-поверхность HTTP), поэтому изоляция тестируется через настоящий ход агента с поддельной моделью, а не через этот эндпойнт. `gateway.tools.allow` оставлен пустым (инвариант).
6. **`~/.openclaw/.env` читается OpenClaw сам.** Не найденные `${VAR}` дают только предупреждение («feature using this value will be unavailable»), а не ошибку: `40-configure.sh` считает такое предупреждение ошибкой.
7. **Остановка шлюза занимает до ~5 минут** (drain-бюджет 330 с) при SIGTERM. Тест-харнес убивает группу процессов SIGKILL, для обычной работы это значит, что `Ctrl+C` может отвечать не сразу.
8. **Allowlist плагинов** `plugins.allow: ["telegram"]` оставляет загруженными только `telegram` и `memory-core` (плагин слота памяти: загружается всё равно; cron выключен, так что «dreaming»-задача не планируется).
9. **Telegram `allowlist` требует хотя бы один id заранее** (пустой список отклоняется валидацией). Поэтому id вводится на шаге настройки.
10. `sandbox explain` для `sessions_spawn` и `sessions_send` показывает «разрешены в песочнице»: подагенты тоже идут в песочницу (`mode: all`), ACP выключен.
11. Docker-контейнер запускается от `uid:gid` хоста (`docker.user`), чтобы workspace был доступен на запись; в образе у этого uid нет записи в passwd и нет привилегий.
12. **Рабочая папка получает каталоги, принадлежащие root.** OpenClaw монтирует в контейнер доступную только для чтения проекцию навыков как вложенный bind-mount `/workspace/.openclaw/sandbox-skills/skills`. Источник mount — копия навыков в состоянии шлюза (`~/.openclaw/sandbox/skills-workspaces/workspace-<hash>/.openclaw/sandbox-skills/skills`), монтируется `ro`. Docker создаёт точку монтирования внутри рабочей папки от имени root: каталоги `<workspace>/.openclaw`, `.openclaw/sandbox-skills`, `.openclaw/sandbox-skills/skills`. Контейнер сохраняется после хода. Это не дыра (контейнер работает от uid 1000, проекция read-only), но такие каталоги нельзя удалить без `sudo` или без запуска контейнера от root. Выяснено на реальном Docker (WSL, Ubuntu 26.04). Тест принимает только эти каталоги и считает любые другие чужие файлы в workspace ошибкой.
13. **`exec` уходит в фон через 10 с** (`yieldMs` по умолчанию 10000, максимум 120000), возвращая «Command still running (session …)». На медленной машине это случается и с короткими проверками. Продолжение — инструментом `process` (`action: poll`). Тест задаёт `yieldMs: 120000` и сам опрашивает процесс.

## 18. Находки этапа 2 (проверены запуском; подробности: `docs/STAGE2.md`)

14. **Плагинные инструменты скрыты Tool Search по умолчанию.** Прямой вызов `local_*` модель увидит только при `tools.toolSearch: false`.
15. **Штатный allow-список песочницы не содержит плагинных инструментов** (`sandbox explain`: только core и каналы). Нужен `tools.sandbox.tools.alsoAllow: ["local_*"]`; `sandbox explain` показывает источник этого ключа. Видимость самих инструментов решает фабрика плагина (режим + сессия).
16. **ID вызова совпадает** между `before_tool_call` (`toolCallId`) и `execute(id, …)`, это позволяет проверить в `execute`, что хук запросил подтверждение именно для этого вызова.
17. **Без канала подтверждения `requireApproval` fail-closed:** вызов отклоняется («Plugin approval unavailable…»), решение приходит в `onResolution` как `cancelled`.
18. **`openclaw plugins inspect` из CLI не показывает регистрации времени исполнения** (`toolNames: []`, `commands: []`, `imported: false`). Реальный список: RPC `commands.list` и `tools.effective` (последний требует существующей сессии) через `openclaw gateway call`.
19. **Команда плагина с `requireAuth: true` не вызывается из `chat.send` CLI/webchat** (отправитель не авторизован, ни `ownerAllowFrom`, ни `commands.allowFrom` это не меняют). Поэтому `/mode` проверяется юнит-тестами и вручную в Telegram, обходной режим в плагин не добавлялся.
20. **Плагин на TypeScript без сборки.** Загрузчик берёт `index.ts`; чтобы тот же код запускался и `node --test` (удаление типов), в нём нет конструкций, требующих трансформации (parameter properties, enum).
21. **Плагин в `plugins.load.paths`** достаточно перечислить в `plugins.allow` и `plugins.entries.<id>`; путь передаётся через `${FERRUM_REPO}` из `~/.openclaw/.env`.
